# Lesson 06 — DohaStudio 제작 기록과 Portfolio 정리

## 목표
한 곡을 만든 과정 전체를 재현 가능한 제작 기록으로 남긴다. 결과 음원만 보관하지 않고 어떤 판단과 수정이 있었는지 추적한다.

## 1. DohaStudio Trace

```text
DohaMusic Project ID:
Composition / Snapshot:
Generation Jobs:
Artifacts:
Selected result:
Provider metadata:
Screens used:
External DAW used:
```

## 2. Version History

```text
v0 — initial idea
v1 — first generated candidate
v2 — selected candidate
v3 — human edit
v4 — mix
v5 — master/final
```

각 Version마다 바뀐 이유를 한 줄 이상 적는다.

## 3. Product Gap
음악 제작을 하면서 프로그램에 부족했던 기능을 따로 기록한다.

```text
Need:
Music reason:
Current status: CURRENT / FOUNDATION / TARGET
Current workaround:
Possible owner repository:
Priority for next song:
```

예:
```text
Need: section-level melody editing
Music reason: chorus hook is good but final 2 bars need revision
Current status: TARGET
Current workaround: external DAW
Possible owner repository: DohaMusic
```

## 4. Learning Summary

```text
Strongest skill this project:
Weakest skill:
Theory I actually used:
Theory I still cannot hear reliably:
AI mistake I learned to recognize:
Arrangement mistake I repeated:
Mix mistake I repeated:
```

## 5. Portfolio Note
포트폴리오에 공개할 때는 기술 설명과 음악 설명을 분리한다.

### Music
```text
Concept:
Genre:
My composition/production contribution:
Main musical decision:
```

### System
```text
DohaStudio workflow used:
AI-assisted steps:
Human edits:
Version/provenance handling:
```

AI를 사용한 부분을 숨기지도, 모든 결과를 AI에게 돌리지도 않는다. 사람이 실제로 한 기획·선택·수정·편곡·Mix 작업을 구체적으로 기록한다.

## 6. 다음 곡으로 넘길 것
첫 Demo가 끝나면 다음 곡에서 한 가지 학습 목표를 강화한다.

```text
Next song focus:
Example: stronger motif development / better bass groove / cleaner vocal prosody / more deliberate arrangement
```

한 곡에서 모든 기술을 완벽하게 하려고 하지 않는다.
