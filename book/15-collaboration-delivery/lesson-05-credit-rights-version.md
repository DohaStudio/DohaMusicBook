# Lesson 05 — Credits, Split, Rights, Version

## 목표
파일 전달과 음악적 기여 기록을 분리하지 않고 함께 관리한다.

## 1. Credit 기록
작업이 끝난 뒤 기억에 의존하지 않는다.

```text
Composition:
Lyrics:
Arrangement:
Production:
Programming:
Vocal:
Recording:
Editing:
Mix:
Master:
```

## 2. Split
공동작업에서 저작 지분이나 정산 기준이 필요하다면 발매 직전에 처음 이야기하지 말고 가능한 한 일찍 논의한다. 실제 계약·법률 판단은 관할과 상황에 따라 별도 검토한다.

## 3. Rights Source Log

```text
Sample / loop:
Source:
License checked:
Commercial use:
Redistribution restriction:
Attribution:
AI training restriction:
```

Plugin/SoundFont/AI service/Voice consent도 같은 방식으로 별도 기록한다.

## 4. Version Authority
팀 안에서 'final', 'final2', 'real-final'이 반복되지 않게 승인 기준을 정한다.

```text
v01 draft
v02 arrangement approved
v03 vocal approved
v04 mix approved
v05 master approved
```

## 5. 변경 이력

```text
Version:
Date:
Changed by:
What changed:
Why:
Approved by:
Supersedes:
```

## DohaStudio 연결
AssetVersion, Artifact, CompositionSnapshot과 provenance는 사람의 Version Log와 같은 문제를 더 구조적으로 해결하기 위한 기반이다. 시스템 ID가 있어도 사람이 이해할 수 있는 변경 이유와 Credit은 별도로 남기는 것이 좋다.

## 완료 체크
- [ ] Credit 역할을 구분해 적었다.
- [ ] Rights Source Log를 만들었다.
- [ ] Version naming과 승인 기준을 정했다.
- [ ] 변경 이유를 기록했다.
