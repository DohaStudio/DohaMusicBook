## 왜 필요한가

좋은 곡을 만들었더라도 전달 과정이 불명확하면 다음 문제가 생긴다.

- 최신 파일이 무엇인지 모른다.
- BPM/Key가 전달되지 않는다.
- Mix Engineer가 의도하지 않은 Reference를 추측한다.
- Vocal Take가 뒤섞인다.
- Stem이 시작 위치가 달라 Sync가 깨진다.
- 누가 어떤 작업을 했는지 Credit이 남지 않는다.
- 상업 이용이 불가능한 Sample이 뒤늦게 발견된다.

## 기본 전달 원칙

```text
한 곡 = 하나의 명확한 Project identity
한 파일 = 역할이 드러나는 이름
한 수정 = 새 Version
한 전달 = Brief + Audio + Metadata + Notes
한 승인 = 누가 언제 무엇을 승인했는지 기록
```

## 권장 파일 이름 예시

```text
one-step_demo_v03_2026-08-23.wav
one-step_vocal-lead_comp_v02.wav
one-step_inst_mix-v04.wav
one-step_stem_drums.wav
one-step_stem_bass.wav
```

실제 팀 규칙이 있다면 그 규칙을 우선한다.

## DohaStudio 연결

DohaStudio에서는 장기적으로 Project, AssetVersion, Artifact, CompositionSnapshot, Job lineage가 사람이 수동으로 하던 Version/Source 추적을 시스템 안에서 보존해야 한다. 하지만 현재 구현되지 않은 협업·공유·원격 승인 기능을 이미 있다고 설명하지 않는다.

## Part 완료 기준

- 협업 시작 Brief를 작성할 수 있다.
- Recording Take를 구분해 전달할 수 있다.
- Mix/Master 전달 파일을 준비할 수 있다.
- Stem과 Final Deliverable의 차이를 안다.
- Credit/권리/Version을 별도 기록한다.
