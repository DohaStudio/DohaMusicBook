```text

Appendix     제작 환경 / 장비 / 파일 관리
```

## 3. 학습 순서 검수

학습 순서는 `기초 음악 문법 → 제작 기술 → AI → 프로그램/코드 → 완성 → 반복 훈련 → 협업`을 따른다.

처음부터 모든 Part를 완독할 필요는 없다.

```text

11 ↔ 12

외부 협업 시작:
15
```

## 4. CURRENT / FOUNDATION / TARGET 검수

DohaStudio 관련 설명에서는 다음 규칙을 유지한다.

- `CURRENT`: 최신 기준 브랜치에서 실제 사용할 수 있는 기능
- `FOUNDATION`: Domain/Contract/Fake/Mock/Runtime 골격은 있으나 최종 제품 기능은 아님
- `TARGET`: 아직 구현되지 않은 목표 기능

특히 다음 기능은 현재 기능으로 오기록하지 않는다.

```text
mutable Track/Clip 완전 편집
MIDI Track / Piano Roll
SoundFont engine integration
완성형 Mixer / Automation
실제 DohaLM / DohaAudio production transport
완성형 Reference Analysis UI
완성형 Composition Evaluation
```

프로그램이 개발되면 Part 11~12는 반드시 원본 저장소의 최신 authority 문서를 다시 읽고 갱신한다.

## 5. 저작권 / 출처 검수

DohaMusicBook은 상업 도서의 본문을 복제하지 않는다.

참고 자료에서는 다음만 가져온다.

- 공부해야 할 주제
- 일반적인 음악 용어
- 학습 범위에 대한 아이디어

설명, 예제, 실습, DohaStudio mapping과 프로그램 사용법은 독립적으로 작성한다.

## 6. 아직 채워야 할 것

v0.1은 **완성된 출판용 책**이 아니라 실제 공부를 시작할 수 있는 curriculum baseline이다.

학습 과정에서 다음이 축적되어야 한다.

- 직접 분석한 실제 곡 기록
- 직접 만든 MIDI/Audio 예제
- 코드 진행·Motif·Groove 연습 결과
- DohaMusic 실행 화면 기반 사용 노트
- AI Candidate A/B 기록
- Demo Song 제작 기록
- Product Gap
- 실제 SoundFont/Plugin license evidence
- 최신 DohaStudio 구현과의 상태 갱신

## 7. 병합 전 Git 상태

검수 시점 기준 `main`과 작업 브랜치의 merge base는 동일하고 작업 브랜치는 `main`보다 앞서 있으며 뒤처진 commit은 없다. 따라서 별도의 base sync가 필요한 상태는 아니다.

GitHub PR은 Draft 상태로 유지한다. 실제 병합 전에는 문서 링크와 최신 DohaStudio 구현 상태를 한 번 더 확인한 뒤 Ready for review로 전환한다.
